# Contributing

Contributions are welcome while the project is in beta.

## Principles

- Preserve the read-only Gmail boundary.
- Do not include real email data in issues, tests, examples, screenshots, or pull requests.
- Keep organization, subscription stream, and receiving account as separate concepts.
- Prefer conservative classification when a stream may be protected.
- Present inferred subscription origins as LIKELY or UNCERTAIN, never as confirmed facts.
- Keep the dashboard focused on Subscriptions and Newsletters.

## Changes

For skill changes, describe the realistic request that motivated the change and the observed failure or ambiguity. Avoid adding rules for hypothetical edge cases without evidence.

For UI changes, use fictional data and confirm Demo Mode remains screenshot-safe.

Run the checks in [TESTING.md](TESTING.md) before opening a pull request.
